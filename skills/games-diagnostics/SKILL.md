## Telemetry & debug probes

- **The probe pair violates the trailer rule by construction:** `git revert` auto-generates its commit message with NO `Co-Authored-By` trailer. Either amend the revert message at creation to add the trailer, or plan to drop the byte-net-zero pair via rebase pre-PR (verify the branch diff hash identical pre/post: `git diff origin/main..HEAD | git hash-object --stdin`). Caught at whole-branch review — the last rewritable window. (what-is-dark phase-3a M1, 2026-07-25.)
- **Temporary probe code lands as ONE purely-additive commit and is removed by `git revert`, never hand-deletion.** Hand-removal of a probe passed grep-zero (probe markers), full GUT, and a clean headless launch — and still left a structural residue (a variable extraction the probe diff introduced) that only a byte-diff against the pre-probe commit caught. Grep-zero proves marker removal, not structural revert; revert is byte-exact by construction. Mark every probe block `DEBUG PROBE — remove before gates` regardless, and verify removal with `git diff <pre-probe-sha> HEAD -- <files>` expecting empty. (what-is-dark momentum-lab, 2026-07-24.)
- **Rates/derivatives from tick telemetry: compute from position/state deltas over the measured span, never from stride-sampled per-tick delta rows.** A sampling stride sharing a factor with any buffering window (input drain, interpolation) phase-locks onto one step of the split and reports a systematically wrong rate — stride-2 prints over a 2-tick yaw drain reported −57°/s where truth was −118.8°/s, convicting a phantom engine bug. (what-is-dark momentum-lab R13, 2026-07-24.)

**A `git revert` of a probe does not remove what the probe accreted in a LATER commit.** Anything added after the reverted commits survives the revert by construction — a `.uid` sidecar added one commit downstream stayed tracked and invisible in a `git status` read taken BEFORE the deletion. The residue check is a grep for probe markers **plus** a `git status` read taken AFTER every deletion, not before. (what-is-dark 3b Step 9.0, 2026-07-28 — the revert itself was byte-correct; the accretion was the miss.)

**Report the WORST case, never the mean, for any claim about a floor or a ceiling.** A mean cannot violate a bound its tail violates, so a mean-only probe table reads as safe while the shipped value is already out of range on some seeds. Every probe column asserting "stays above/below X" carries min/max alongside the average. (dog-eat-dog wave 3a QA-R2e, 2026-07-29: round 1 reported the first-wall margin as a mean of 33.2 against a 25-unit readability floor and shipped it; round 2 added a worst-case column and the worst over 60 seeds was **22.5** — some mornings began already pinned, and it shipped for a full round.)

## Feel-gate tuning loop

**Feel-gate tuning loop** (evaluation/tuning waves; proven over 15 rounds, momentum-lab 2026-07): each round runs ride → symptom split (one focused question if the complaint is ambiguous) → probe-verified diagnosis → user pick → warm redo to the owning implementer chain → re-review. Two hard rules inside the loop: (1) **no constant or geometry change ships without a probe-verified diagnosis first** — three separate rounds found the physics authentic and the real defect elsewhere (layout, scale, turn-window law); an unverified "fix" would have masked each; (2) **any fork encoding a product-feel judgment (parity break, cap widening, geometry redesign) is a user pick, never an orchestrator walk-rule** — games instance of the universal value-judgment rule, and ride-BEFORE-review is the right order for those changes (review a value the user may reject and the round is wasted; log the review debt explicitly with its close condition instead).

**Addendum 2026-07-29 (dog-eat-dog wave 3a QA-R2e) — rule (1) is now n=2 across two projects, and this instance shows WHY the probe is not optional.** The user asked for faster traffic to stop being trapped. Raising the speed band moved trapped time **80.0% → 79.5%** — zero. The lever was coupled to layout: wall spacing scales with `(1 - the same roll)`, so cars speeding up packs the walls tighter by exactly as much as the faster cars help, and you escape one wall into the next. The requested change would have shipped as a fix with a plausible story attached. **A tuning lever that also appears in a layout/spacing term can measure exactly zero net effect — probe the lever in isolation before shipping it, and probe the term you think is unrelated.** What actually moved the number was a different lever entirely (per-car jitter, 60.1% → 43.7%), and the real fix was geometric: the weave cost is ABSOLUTE (`pin_gap + block_margin`) while room between obstacles scales with route length, so lengthening the route is the only way to buy traffic its speed.

**Corollary — a tunable expressed as a FRACTION of a dimension, but bounded by an ABSOLUTE quantity, silently re-solves whenever that dimension changes.** Record the solve in the tunable's doc comment, and re-solve it in the same round the dimension moves. (Same wave: intra-wave position jitter was `0.015 * route_length` and had to stay under the absolute 30-unit pin gap. Route 400 → 900 doubled it to ±13.5 and the wave stopped reading as a wall; re-solved to `0.007` to hold the original ±6 units. No tunable is touched when this breaks — it surfaces as an unrelated-looking property-test failure.)
